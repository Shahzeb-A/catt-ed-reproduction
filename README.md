# CATT ED reproduction on the public held-out split

Reproduces the released CATT encoder-decoder (`best_ed_mlm_ns_epoch_178.pt`, abjadai/catt v2) on
the held-out split of the public release, on CPU, with every number regenerated by one command
from a committed config.

## Result

Released ED on the 2,324 line held-out split, CPU (MacBook Air, Apple M3, 8 GB, 4 threads, batch 16):

| | DER with case endings | DER without | WER with | WER without |
|---|---|---|---|---|
| upstream `compute_der.py` | **0.505%** | 0.309% | 1.889% | 1.117% |
| letters only (`src/metrics.py`) | 0.637% | 0.502% | 1.889% | 1.069% |

1,940 diacritic errors in 304,558 letters. The upstream scorer divides the same errors by 383,693
positions (letters, spaces, BOS and EOS); `src/metrics.py` reproduces its figure independently as
0.5051% (`upstream_conv_der_ce_editdistance`).

Throughput: **141.8 words/s** (76,811 words in 541.5 s, decode only, after a 2 line warmup), peak
RSS 1.4 GB. This is an 8 GB laptop, so it is a floor, not a comparison with other CPUs.

Altered lines (output base letters differ from the input): **0** of 2,324.
List: [`results/released_ed_heldout_cpu/altered_lines.tsv`](results/released_ed_heldout_cpu/altered_lines.tsv).

Full numbers, sha256 of every input and prediction file, and the environment are in
[`results/released_ed_heldout_cpu/metrics.json`](results/released_ed_heldout_cpu/metrics.json);
the exact config used is next to it in `resolved_config.json`.

## What the split is

`dataset/test/test.txt` from the v2 release `dataset.zip` (2,500 lines), selected the way upstream
`TashkeelDataset` does it: `clean_text`, drop empty lines, keep `5 < len <= 1024`, keep lines whose
share of diacritised positions is at least 0.6. That leaves **2,324 lines, 76,811 words**. Model input
is each gold line with the eight diacritics (U+064B to U+0652) removed. No line in the split contains
dagger alef, tatweel or lam alef ligatures after `clean_text`, so nothing else is stripped.

## Overlap with the training split

`scripts/train_overlap.py` streams `dataset/train/train.txt` (1,739,487 lines, 1,492,372 after
`clean_text` and the length filter) and checks every held-out line against it.

* 760 held-out lines (33%) occur in the training split with identical diacritics; 783 share the
  same undiacritised text.
* On the **1,541 lines with no overlap** (44,859 words) the released ED scores **0.509%** DER with
  case endings (upstream convention, 0.641% letters only); on the 783 overlapping lines, 0.501%.

So the training overlap is not what makes 0.505% low. The split is easy because it is the same
classical register as the training data, which is why the WikiNews figure (5.963%) is the one to
explain. Indices of every overlapping line are in `results/heldout_overlap/overlap.json`.

## Two scorers

1. **Upstream `compute_der.py`**, run unmodified as a subprocess on the prediction files.
2. **`src/metrics.py`**, written from scratch with no upstream code, positional (letter i of the
   reference against letter i of the output), which is only defined when base letters match, so a
   line whose letters changed is listed and kept out of the rates rather than averaged in.

They differ on purpose in two conventions, which is most of why published DER numbers disagree:

* **Denominator.** `compute_der.py` counts every character position including spaces, plus BOS and
  EOS on each line. The letters convention counts Arabic letters only.
* **Without case endings.** `compute_der.py` neutralises the letter before each space, so the case
  ending on the last word of every line is still scored. The letters convention drops the last
  letter of every word.
* `compute_der.py` also scores DER as an edit distance over the label sequence rather than position
  by position, which can only lower the count. `upstream_conv_der_*_editdistance` in `metrics.json`
  reproduces it so the gap can be seen.

## Decoder

Upstream `do_tashkeel_batch` reruns the full decoder over the whole prefix at every step.
`src/cached_decode.py` caches each layer's keys and values and reuses the upstream modules' own
sublayers. `scripts/check_equivalence.py` decodes a length stratified sample with both and compares
outputs byte for byte: **60 of 60 identical** (length stratified, seed 0, batch 16), 530.6 s for the
upstream loop against 22.1 s cached (`results/equivalence_cpu/equivalence.json`).

Upstream `tokenizer.decode` already rebuilds output letters from the input ids and the model only
picks a tag per position, so zero altered lines is mostly a property of the decode, not of the
weights. Two gaps remain upstream. The argmax is not masked against PAD, BOS and EOS, and a PAD
predicted mid line is filtered out before letters and tags are zipped, which shifts every later tag
and drops trailing letters. And `clean_text` deletes or rewrites anything outside its character
range before the model sees it (Latin, digits, punctuation, tatweel, alef wasla, dagger alef,
combining hamza). The first never happened here (0 altered lines); the second is outside this
measurement, because the split is cleaned before it is scored. `tests/test_model.py` checks letter preservation
on random Arabic strings.

## Rerun

```bash
bash scripts/setup.sh                       # venv, upstream at UPSTREAM_SHA, release assets with sha256 checks
.venv/bin/python scripts/eval_released.py --config configs/eval_released_cpu.yaml
.venv/bin/python scripts/score_predictions.py --run released_ed_heldout_cpu   # rescore saved predictions only
.venv/bin/python scripts/check_equivalence.py --n 60
.venv/bin/python scripts/train_overlap.py
.venv/bin/python -m pytest -q
```

## What is not here

* No weights, dataset text or predictions are committed (`.gitignore`); their sha256 values are in
  `metrics.json`. The released .pt weights were uploaded on 2024-07-04, when the LICENSE file was CC BY NC SA
  4.0 (the README said CC BY NC 4.0); the repo moved to Apache 2.0 on 2025-07-18.
* The upstream `benchmarking/` folder (WikiNews and CATT benchmark gold and model outputs) is
  deliberately not checked out by `setup.sh`. Benchmark data is pulled only after its licence is
  approved.
* No GPU numbers yet, and no fine tune yet.
