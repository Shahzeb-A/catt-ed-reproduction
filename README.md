# CATT ED reproduction on the public held out split

Reproduces the released CATT encoder decoder (`best_ed_mlm_ns_epoch_178.pt`, abjadai/catt v2) on
the held out split of the public release, on CPU. Every number comes from a committed config and
is regenerated by `scripts/setup.sh` plus one command.

## Result

Released ED on the 2,324 line held out split, CPU (MacBook Air, Apple M3, 8 GB, 4 threads, batch 16)

| | DER with case endings | DER without | WER with | WER without |
|---|---|---|---|---|
| upstream `compute_der.py` | **0.505%** | 0.309% | 1.889% | 1.117% |
| letters only (`src/metrics.py`) | 0.637% | 0.502% | 1.889% | 1.069% |

Position by position there are 1,940 diacritic errors in 304,558 letters. The upstream scorer
counts 1,938 (it uses edit distance over the tag sequence) and divides by 383,693 positions, which
are letters plus spaces plus BOS and EOS on every line. `src/metrics.py` reproduces the upstream
figure independently as 0.5051% (`upstream_conv_der_ce_editdistance`).

**Altered lines** (output base letters differ from the input) **0** of 2,324, listed in
[`results/released_ed_heldout_cpu/altered_lines.tsv`](results/released_ed_heldout_cpu/altered_lines.tsv)
by index, line number, first differing character and input hash, so no dataset text is committed.

**Throughput** 141.8 words/s (76,811 words in 541.5 s, decode only, after a 2 line warmup), peak
RSS 1.4 GB. This uses the cached decoder below. The unmodified upstream loop is about 24 times
slower on this machine. It is a laptop figure and not comparable with other CPUs or decoders.

Full numbers, the sha256 of every input and prediction file, and the environment are in
[`results/released_ed_heldout_cpu/metrics.json`](results/released_ed_heldout_cpu/metrics.json),
with the exact config next to it in `resolved_config.json`.

## What the split is

`dataset/test/test.txt` from the v2 release `dataset.zip` (2,500 lines), selected the way upstream
`TashkeelDataset` does it. Apply `clean_text`, drop empty lines, keep `5 < len <= 1024`, keep lines
whose share of diacritised positions is at least 0.6. That leaves **2,324 lines, 76,811 words**.
Model input is each gold line with the eight diacritics (U+064B to U+0652) removed. After
`clean_text` no line contains dagger alef, tatweel or lam alef ligatures, so nothing else is stripped.

## Overlap with the training split

`scripts/train_overlap.py` streams `dataset/train/train.txt` (1,739,487 lines, 1,492,372 after
`clean_text` and the length filter) and checks every held out line against it two ways, as a whole
line and by runs of 8 consecutive words. Diacritics are removed on both sides for both checks.

| subset of the 2,324 lines | lines | words | DER with CE, `compute_der.py` | letters only |
|---|---|---|---|---|
| all | 2,324 | 76,811 | 0.505% | 0.637% |
| whole line also in train (760 of them with identical diacritics) | 783 | 31,952 | 0.500% | 0.631% |
| no whole line match | 1,541 | 44,859 | 0.509% | 0.641% |
| no whole line match, 8+ words, no shared 8 word run | 851 | 24,374 | 0.531% | 0.670% |

Of the 1,541 lines with no whole line match, 417 still share an 8 word run with some training line
and 273 are too short to check. Overlap moves DER by a few hundredths of a point, so it is not what
keeps 0.505% low. All subsets are scored by upstream `compute_der.py` and by `src/metrics.py`.
Definitions, every score and the indices of every line in each subset are in
`results/heldout_overlap/overlap.json`.

## Two scorers

1. **Upstream `compute_der.py`**, run unmodified as a subprocess on the prediction files.
2. **`src/metrics.py`**, written from scratch with no upstream code. It is positional (letter i of
   the reference against letter i of the output), which is only defined when base letters match, so
   a line whose letters changed is listed and kept out of the rates rather than averaged in.

They differ on purpose in the conventions that make published DER numbers disagree.

* **Denominator.** `compute_der.py` counts every character position including spaces, plus BOS and
  EOS on each line. The letters convention counts Arabic letters only.
* **Without case endings.** `compute_der.py` neutralises the letter before each space, so the case
  ending on the last word of every line is still scored. The letters convention drops the last
  letter of every word.
* **Alignment.** `compute_der.py` scores DER as an edit distance over the tag sequence, not position
  by position, which can only lower the count. `upstream_conv_der_*_editdistance` in `metrics.json`
  reproduces it so the gap is visible.
* **Shadda order** is normalised by both, so shadda before or after the vowel never counts as an error.

## Decoder

Upstream `do_tashkeel_batch` reruns the full decoder over the whole prefix at every step.
`src/cached_decode.py` caches each layer's keys and values and reuses the upstream modules' own
sublayers. `scripts/check_equivalence.py` decodes a length stratified sample with both and compares
outputs byte for byte. Result **60 of 60 identical** (seed 0, batch 16, inputs up to 592 of the
split's longest 601 characters). On those 2,013 words the upstream loop took 530.6 s (3.8 words/s)
and the cached decoder 22.1 s (91 words/s) (`results/equivalence_cpu/equivalence.json`).
`configs/eval_released_cpu_upstream.yaml` runs the whole split through the upstream loop, and
`scripts/compare_runs.py` diffs it against the cached run line by line.

Upstream `tokenizer.decode` already rebuilds output letters from the input ids and the model only
picks a tag per position, so zero altered lines is mostly a property of the decode, not of the
weights. Two gaps remain upstream.

1. The argmax is not masked against PAD, BOS and EOS. A PAD predicted mid line is filtered out
   before letters and tags are zipped, which shifts every later tag and drops trailing letters.
   It never happened here (0 altered lines).
2. `clean_text`, and `split_tashkeel_from_text` inside `encode`, delete or rewrite characters
   before the model sees them (Latin, digits, punctuation, tatweel, alef wasla, dagger alef,
   combining hamza, final form lam alef ligatures). This split is cleaned before it is scored, so it
   cannot show this.

`tests/test_model.py` checks letter preservation on random Arabic strings.

## Rerun

Needs git, curl and Python 3.12 (uv is used if available). Tested on macOS arm64 with git 2.50.
`requirements.lock` is the exact environment the committed results came from.

```bash
bash scripts/setup.sh    # venv, upstream at UPSTREAM_SHA, release assets with sha256 checks
.venv/bin/python scripts/eval_released.py --config configs/eval_released_cpu.yaml
.venv/bin/python scripts/score_predictions.py --run released_ed_heldout_cpu   # rescore saved predictions only
.venv/bin/python scripts/check_equivalence.py --n 60
.venv/bin/python scripts/train_overlap.py
.venv/bin/python -m pytest -q
```

On a GPU, `configs/eval_released_gpu.yaml` is the same run with `device: cuda`, and `metrics.json`
then also records the GPU, CUDA, driver and peak GPU memory.

## What is not here

* No weights, dataset text or predictions are committed (see `.gitignore`). Their sha256 values are
  in `metrics.json`. The released .pt weights were uploaded on 2024-07-04, when the LICENSE file was
  CC BY NC SA 4.0 (the README said CC BY NC 4.0). The repo moved to Apache 2.0 on 2025-07-18.
* The upstream `benchmarking/` folder (WikiNews and CATT benchmark gold and model outputs) is never
  fetched. `setup.sh` clones without blobs, sets the sparse pattern before checkout, and stops if any
  benchmarking blob is in the local git store. Benchmark data comes down only after its licence is
  approved.
* No GPU numbers yet, and no fine tune yet.
